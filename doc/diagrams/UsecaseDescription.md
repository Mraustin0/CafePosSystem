# Use Case Description — Cafe POS System

เอกสารอธิบาย Use Case ของระบบ POS สำหรับร้านกาแฟ จัดทำตามแผนภาพ Use Case Diagram (รายละเอียดขั้นตอนบางส่วนอนุมานจากชื่อ Use Case และหน้าจอของระบบ ปรับแก้ให้ตรงกับระบบจริงได้)

## 1. ผู้กระทำ (Actors)

| Actor | คำอธิบาย |

## 3. รายละเอียด Use Case

### 3.1 Authentication & Profile

#### UC-01 Login

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** ผู้ใช้เข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่านเพื่อเริ่มใช้งาน

**เงื่อนไขก่อน:** มีบัญชีผู้ใช้ในระบบและบัญชียังเปิดใช้งานอยู่

**เงื่อนไขหลัง:** ระบบสร้างเซสชันและแสดงหน้าจอตามสิทธิ์ (Cashier เห็นหน้า POS, Admin เห็นเมนูหลังบ้านเพิ่ม)

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เปิดหน้าเข้าสู่ระบบ
2. ผู้ใช้กรอกชื่อผู้ใช้และรหัสผ่าน แล้วกดเข้าสู่ระบบ
3. ระบบตรวจสอบข้อมูลกับฐานข้อมูล
4. ระบบนำผู้ใช้เข้าสู่หน้าหลักตามสิทธิ์

**ลำดับเหตุการณ์ทางเลือก**

- 3a. ข้อมูลไม่ถูกต้อง: ระบบแสดงข้อความผิดพลาดและให้กรอกใหม่
- 3b. บัญชีถูกปิดใช้งาน: ระบบปฏิเสธการเข้าสู่ระบบ

#### UC-02 Logout

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** ผู้ใช้ออกจากระบบเมื่อเลิกใช้งานหรือเปลี่ยนกะ

**เงื่อนไขก่อน:** ผู้ใช้เข้าสู่ระบบอยู่

**เงื่อนไขหลัง:** เซสชันสิ้นสุดและระบบกลับไปหน้า Login

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้กดออกจากระบบ
2. ระบบขอให้ยืนยัน
3. ผู้ใช้ยืนยัน
4. ระบบล้างเซสชันและกลับไปหน้า Login

**ลำดับเหตุการณ์ทางเลือก**

- 3a. ผู้ใช้ยกเลิก: ระบบคงอยู่ที่หน้าเดิม

#### UC-03 View / Edit Profile

**ผู้ใช้:** Cashier, Admin

**คำอธิบาย:** ผู้ใช้ดูและแก้ไขข้อมูลส่วนตัวของตนเอง

**เงื่อนไขก่อน:** ผู้ใช้เข้าสู่ระบบอยู่

**เงื่อนไขหลัง:** ข้อมูลโปรไฟล์ถูกอัปเดตตามที่แก้ไข

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เปิดหน้าโปรไฟล์
2. ระบบแสดงข้อมูลปัจจุบัน
3. ผู้ใช้กดแก้ไขและกรอกข้อมูลใหม่
4. ผู้ใช้กดบันทึก
5. ระบบตรวจสอบความถูกต้องและบันทึกข้อมูล พร้อมแจ้งผลสำเร็จ

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ข้อมูลไม่ครบหรือรูปแบบไม่ถูกต้อง: ระบบแจ้งเตือนและไม่บันทึก
- 4a. ผู้ใช้ยกเลิก: ระบบคงข้อมูลเดิม

#### UC-04 Change Password

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** ผู้ใช้เปลี่ยนรหัสผ่านของตนเอง

**เงื่อนไขก่อน:** ผู้ใช้เข้าสู่ระบบอยู่

**เงื่อนไขหลัง:** รหัสผ่านใหม่ถูกบันทึก (เข้ารหัส) และใช้ได้ในการเข้าสู่ระบบครั้งถัดไป

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เลือกเปลี่ยนรหัสผ่าน
2. ผู้ใช้กรอกรหัสผ่านเดิม รหัสผ่านใหม่ และยืนยันรหัสผ่านใหม่
3. ระบบตรวจสอบรหัสผ่านเดิมและเงื่อนไขของรหัสผ่านใหม่
4. ระบบบันทึกรหัสผ่านใหม่และแจ้งผลสำเร็จ

**ลำดับเหตุการณ์ทางเลือก**

- 3a. รหัสผ่านเดิมไม่ถูกต้อง: ระบบแจ้งเตือนให้กรอกใหม่
- 3b. รหัสผ่านใหม่ไม่ตรงกับช่องยืนยัน หรือไม่ผ่านเงื่อนไข: ระบบแจ้งเตือนและไม่บันทึก

### 3.2 Order & POS Management

#### UC-05 Create Order

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** เริ่มสร้างออเดอร์ใหม่และรวบรวมรายการที่ลูกค้าสั่ง มีความสัมพันธ์ «include» กับ UC-06 และ UC-07 และมี UC-09 เป็น «extend»

**เงื่อนไขก่อน:** ผู้ใช้เข้าสู่ระบบอยู่

**เงื่อนไขหลัง:** ได้ออเดอร์สถานะรอชำระเงินที่มีรายการอย่างน้อย 1 รายการ

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เริ่มออเดอร์ใหม่
2. ผู้ใช้เลือกดูสินค้า (UC-06 Browse Products by Category)
3. ผู้ใช้เพิ่มสินค้าลงออเดอร์ (UC-07 Add Item to Order) และทำซ้ำจนครบรายการ
4. ระบบแสดงรายการและยอดรวมของออเดอร์
5. (ถ้ามี) ผู้ใช้เลือกใช้โปรโมชัน (UC-09 Apply Promotion)
6. ผู้ใช้กดชำระเงิน (UC-12 Process Payment)

**ลำดับเหตุการณ์ทางเลือก**

- 6a. ออเดอร์ไม่มีรายการ: ระบบไม่อนุญาตให้ไปขั้นตอนชำระเงิน

#### UC-06 Browse Products by Category (incl. Search)

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** แสดงสินค้าตามหมวดหมู่ (เช่น กาแฟ ชา ขนม) และค้นหาสินค้าจากชื่อ เป็นส่วนหนึ่งของ UC-05 («include»)

**เงื่อนไขก่อน:** มีสินค้าที่เปิดใช้งานอยู่ในระบบ

**เงื่อนไขหลัง:** ผู้ใช้เห็นสินค้าที่ต้องการและเลือกสินค้าได้

**ลำดับเหตุการณ์หลัก**

1. ระบบแสดงรายการหมวดหมู่
2. ผู้ใช้เลือกหมวดหมู่
3. ระบบแสดงสินค้าในหมวดนั้น
4. (ถ้าต้องการ) ผู้ใช้พิมพ์คำค้นหา ระบบกรองผลตามชื่อสินค้า

**ลำดับเหตุการณ์ทางเลือก**

- 4a. ไม่พบสินค้าตามคำค้นหา: ระบบแจ้งว่าไม่พบสินค้า
- สินค้าที่ปิดใช้งานจะไม่แสดงในรายการ

#### UC-07 Add Item to Order

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** เพิ่มสินค้าที่เลือกลงในออเดอร์ พร้อมจำนวนและรายละเอียด เป็นส่วนหนึ่งของ UC-05 («include») และมี UC-08 เป็น «extend»

**เงื่อนไขก่อน:** ผู้ใช้เลือกสินค้าแล้ว และมีออเดอร์ที่กำลังสร้างอยู่

**เงื่อนไขหลัง:** รายการสินค้าถูกเพิ่มลงออเดอร์ และยอดรวมถูกคำนวณใหม่

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้แตะสินค้า
2. ระบบเปิดหน้าต่างตัวเลือกของสินค้า
3. กรณีเครื่องดื่ม ผู้ใช้เลือกตัวเลือกเพิ่มเติม (UC-08) ส่วนกรณีขนมจะข้ามขั้นตอนนี้
4. ผู้ใช้ปรับจำนวนและระบุหมายเหตุ (ถ้ามี)
5. ผู้ใช้กดเพิ่มลงรายการสั่งซื้อ
6. ระบบคำนวณราคาต่อหน่วย เพิ่มรายการลงออเดอร์ และปิดหน้าต่าง

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ผู้ใช้ปิดหน้าต่าง: ระบบไม่เพิ่มรายการ
- จำนวนต่ำสุดคือ 1

#### UC-08 Select Add-ons & Sweetness Level

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** เลือกตัวเลือกเสริมของเครื่องดื่ม ได้แก่ รูปแบบเครื่องดื่ม (เย็น ร้อน ปั่น) ระดับการคั่วเมล็ดกาแฟ ระดับความหวาน (100%, 75%, 50%, 25%, 0%) และ Add-ons เป็น «extend» ของ UC-07 ใช้เมื่อสินค้าเป็นเครื่องดื่ม

**เงื่อนไขก่อน:** ผู้ใช้อยู่ในหน้าต่างตัวเลือกของเครื่องดื่ม

**เงื่อนไขหลัง:** ตัวเลือกที่เลือกถูกรวมในรายการ และราคาต่อหน่วยเท่ากับราคาฐาน + ราคารูปแบบเครื่องดื่ม + ราคา Add-ons

**ลำดับเหตุการณ์หลัก**

1. ระบบแสดงเฉพาะตัวเลือกที่เปิดใช้งานของสินค้านั้น
2. ผู้ใช้เลือกรูปแบบเครื่องดื่มและระดับการคั่ว
3. ผู้ใช้เลือกระดับความหวาน
4. ผู้ใช้เลือก Add-ons ที่ผูกกับสินค้า (เลือกได้หลายรายการ)
5. ผู้ใช้ระบุโน้ตพิเศษ (ถ้ามี)
6. ระบบสรุปตัวเลือกเป็นรายละเอียดของรายการ

**ลำดับเหตุการณ์ทางเลือก**

- 4a. ผู้ใช้ไม่เลือก Add-on: ระบบแสดงว่า ไม่มีเพิ่มเติม
- Add-on ที่ปิดใช้งานจะไม่แสดงให้เลือก

#### UC-09 Apply Promotion

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** ใช้โปรโมชันกับออเดอร์เพื่อลดราคา เป็น «extend» ของ UC-05 ใช้เมื่อมีโปรโมชันที่เข้าเงื่อนไข

**เงื่อนไขก่อน:** มีออเดอร์ที่มีรายการสินค้า และมีโปรโมชันที่เปิดใช้งานอยู่

**เงื่อนไขหลัง:** ออเดอร์มีส่วนลดและยอดสุทธิถูกคำนวณใหม่

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้กดใช้โปรโมชัน
2. ระบบแสดงโปรโมชันที่เปิดใช้งานและเข้าเงื่อนไข
3. ผู้ใช้เลือกโปรโมชัน
4. ระบบคำนวณส่วนลดและแสดงยอดสุทธิ

**ลำดับเหตุการณ์ทางเลือก**

- 3a. ออเดอร์ไม่เข้าเงื่อนไขของโปรโมชัน: ระบบแจ้งเหตุผลและไม่ใช้ส่วนลด
- 4a. ผู้ใช้ยกเลิกโปรโมชัน: ระบบคืนยอดเดิม

#### UC-10 Edit / Remove Order Item

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** แก้ไขหรือลบรายการสินค้าที่อยู่ในออเดอร์ก่อนชำระเงิน

**เงื่อนไขก่อน:** ออเดอร์ยังไม่ชำระเงินและมีรายการสินค้า

**เงื่อนไขหลัง:** รายการในออเดอร์ถูกแก้ไขหรือลบ และยอดรวมถูกคำนวณใหม่

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เลือกรายการในออเดอร์
2. ผู้ใช้เลือกแก้ไข (จำนวน ตัวเลือก หรือโน้ต) หรือลบรายการ
3. ระบบขอให้ยืนยันกรณีลบ
4. ระบบอัปเดตออเดอร์และคำนวณยอดใหม่

**ลำดับเหตุการณ์ทางเลือก**

- 4a. ลบรายการสุดท้าย: ออเดอร์เหลือว่างและไม่สามารถชำระเงินได้
- ออเดอร์ที่ชำระเงินแล้วไม่สามารถแก้ไขได้

#### UC-11 Cancel Order

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** ยกเลิกออเดอร์ทั้งหมดที่ยังไม่ชำระเงิน

**เงื่อนไขก่อน:** ออเดอร์ยังไม่ชำระเงิน

**เงื่อนไขหลัง:** ออเดอร์มีสถานะยกเลิกและรายการในหน้าสั่งซื้อถูกล้าง

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้กดยกเลิกออเดอร์
2. ระบบขอให้ยืนยัน
3. ผู้ใช้ยืนยัน
4. ระบบเปลี่ยนสถานะเป็นยกเลิกและล้างรายการ

**ลำดับเหตุการณ์ทางเลือก**

- 3a. ผู้ใช้ไม่ยืนยัน: ระบบคงออเดอร์เดิม

### 3.3 Payment & Receipts

#### UC-12 Process Payment

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** รับชำระเงินสำหรับออเดอร์ มีความสัมพันธ์ «include» กับ UC-13 และ UC-14

**เงื่อนไขก่อน:** ออเดอร์มีรายการสินค้าและมียอดสุทธิมากกว่า 0

**เงื่อนไขหลัง:** ออเดอร์ถูกบันทึกเป็นชำระแล้วและปรากฏในประวัติออเดอร์

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้กดชำระเงิน
2. ผู้ใช้เลือกวิธีชำระเงิน (UC-13)
3. ระบบดำเนินการตามวิธีที่เลือก: เงินสด ให้กรอกจำนวนเงินที่รับและระบบคำนวณเงินทอน / QR ระบบแสดง QR ตามยอดสุทธิและรอการยืนยัน
4. ผู้ใช้ยืนยันการรับเงิน
5. ระบบบันทึกการชำระเงินและเปลี่ยนสถานะออเดอร์เป็นชำระแล้ว
6. ระบบแสดงและพิมพ์ใบเสร็จ (UC-14)

**ลำดับเหตุการณ์ทางเลือก**

- 3a. เงินสดที่รับน้อยกว่ายอดสุทธิ: ระบบไม่อนุญาตให้ยืนยัน
- 3b. ชำระ QR ไม่สำเร็จหรือหมดเวลา: ระบบแจ้งเตือนและให้เลือกวิธีชำระใหม่หรือยกเลิก

#### UC-13 Select Payment Method (Cash / QR)

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** เลือกวิธีชำระเงินระหว่างเงินสดหรือ QR เป็นส่วนหนึ่งของ UC-12 («include»)

**เงื่อนไขก่อน:** ผู้ใช้อยู่ในขั้นตอนการชำระเงิน

**เงื่อนไขหลัง:** ระบบทราบวิธีชำระเงินที่ใช้กับออเดอร์นี้

**ลำดับเหตุการณ์หลัก**

1. ระบบแสดงตัวเลือกวิธีชำระเงิน (เงินสด / QR)
2. ผู้ใช้เลือกวิธีชำระเงิน
3. ระบบบันทึกวิธีที่เลือกและแสดงหน้าจอที่เกี่ยวข้อง

**ลำดับเหตุการณ์ทางเลือก**

- 2a. ผู้ใช้เปลี่ยนวิธีชำระก่อนยืนยัน: ระบบเปลี่ยนไปหน้าจอของวิธีใหม่

#### UC-14 View / Print Receipt

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** แสดงและพิมพ์ใบเสร็จหลังชำระเงิน มีเลขที่ออเดอร์ วันที่เวลา ชื่อพนักงาน รายการสินค้าพร้อมตัวเลือก ส่วนลด ยอดรวม และวิธีชำระเงิน เป็นส่วนหนึ่งของ UC-12 («include»)

**เงื่อนไขก่อน:** การชำระเงินสำเร็จ

**เงื่อนไขหลัง:** ใบเสร็จถูกแสดงบนหน้าจอและ/หรือพิมพ์ออกมา

**ลำดับเหตุการณ์หลัก**

1. ระบบสร้างใบเสร็จจากข้อมูลออเดอร์
2. ระบบแสดงใบเสร็จบนหน้าจอ
3. ผู้ใช้กดพิมพ์
4. ระบบส่งใบเสร็จไปยังเครื่องพิมพ์

**ลำดับเหตุการณ์ทางเลือก**

- 4a. ไม่พบเครื่องพิมพ์หรือพิมพ์ไม่สำเร็จ: ระบบแจ้งเตือนและให้ดูใบเสร็จบนหน้าจอหรือพิมพ์ซ้ำภายหลัง

### 3.4 Order History

#### UC-15 Search Order History

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** ค้นหาออเดอร์ย้อนหลังด้วยเลขที่ออเดอร์ วันที่ สถานะ หรือวิธีชำระเงิน มีความสัมพันธ์ «include» กับ UC-16

**เงื่อนไขก่อน:** ผู้ใช้เข้าสู่ระบบอยู่

**เงื่อนไขหลัง:** ผู้ใช้เห็นรายการออเดอร์ตามเงื่อนไขที่ค้นหา

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เปิดหน้าประวัติออเดอร์
2. ผู้ใช้ระบุเงื่อนไขการค้นหา
3. ระบบแสดงรายการออเดอร์ที่ตรงเงื่อนไข
4. ผู้ใช้เลือกออเดอร์ที่ต้องการ
5. ระบบแสดงรายละเอียดออเดอร์ (UC-16)

**ลำดับเหตุการณ์ทางเลือก**

- 3a. ไม่พบออเดอร์: ระบบแจ้งว่าไม่พบข้อมูล

#### UC-16 View Order Detail

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** แสดงรายละเอียดออเดอร์ ได้แก่ รายการสินค้า ตัวเลือก โน้ต ส่วนลด ยอดรวม วิธีชำระเงิน เวลา และพนักงานที่ทำรายการ เป็นส่วนหนึ่งของ UC-15 และ UC-17 («include»)

**เงื่อนไขก่อน:** มีออเดอร์ในระบบ

**เงื่อนไขหลัง:** ผู้ใช้เห็นข้อมูลออเดอร์ครบถ้วน

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้เลือกออเดอร์
2. ระบบดึงข้อมูลออเดอร์
3. ระบบแสดงรายละเอียดทั้งหมด

**ลำดับเหตุการณ์ทางเลือก**

- 2a. ไม่พบข้อมูลออเดอร์: ระบบแจ้งข้อผิดพลาด

#### UC-17 Reprint Receipt

**ผู้กระทำ:** Cashier, Admin

**คำอธิบาย:** พิมพ์ใบเสร็จซ้ำของออเดอร์ที่ชำระแล้ว มีความสัมพันธ์ «include» กับ UC-16

**เงื่อนไขก่อน:** ออเดอร์ที่เลือกชำระเงินแล้ว

**เงื่อนไขหลัง:** ใบเสร็จฉบับสำเนาถูกพิมพ์

**ลำดับเหตุการณ์หลัก**

1. ผู้ใช้ค้นหาและเลือกออเดอร์
2. ระบบแสดงรายละเอียดออเดอร์ (UC-16)
3. ผู้ใช้กดพิมพ์ใบเสร็จซ้ำ
4. ระบบพิมพ์ใบเสร็จโดยระบุว่าเป็นสำเนา

**ลำดับเหตุการณ์ทางเลือก**

- 3a. ออเดอร์ถูกยกเลิกหรือยังไม่ชำระ: ระบบไม่อนุญาตให้พิมพ์
- 4a. พิมพ์ไม่สำเร็จ: ระบบแจ้งเตือนให้ลองใหม่

### 3.5 Back-Office Administration

#### UC-18 Manage Products

**ผู้กระทำ:** Admin

**คำอธิบาย:** เพิ่ม แก้ไข ลบ หรือปิดใช้งานสินค้า (ชื่อ ราคา หมวดหมู่ รูปภาพ และตัวเลือกของสินค้า)

**เงื่อนไขก่อน:** Admin เข้าสู่ระบบแล้ว

**เงื่อนไขหลัง:** ข้อมูลสินค้าถูกอัปเดตและมีผลกับหน้าสั่งซื้อ

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้าจัดการสินค้า
2. Admin เลือกเพิ่มสินค้าใหม่ หรือเลือกสินค้าเพื่อแก้ไข/ลบ
3. Admin กรอกหรือแก้ไขข้อมูลสินค้า
4. Admin กดบันทึก
5. ระบบตรวจสอบข้อมูลและบันทึก พร้อมแสดงรายการล่าสุด

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ข้อมูลไม่ครบหรือราคาไม่ถูกต้อง: ระบบแจ้งเตือนและไม่บันทึก
- 2a. ลบสินค้าที่เคยอยู่ในออเดอร์: ระบบแนะนำให้ปิดใช้งานแทนการลบ

#### UC-19 Manage Categories

**ผู้กระทำ:** Admin

**คำอธิบาย:** เพิ่ม แก้ไข หรือลบหมวดหมู่สินค้า (เช่น กาแฟ ชา ขนม)

**เงื่อนไขก่อน:** Admin เข้าสู่ระบบแล้ว

**เงื่อนไขหลัง:** หมวดหมู่ถูกอัปเดตและแสดงในหน้าสั่งซื้อ

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้าจัดการหมวดหมู่
2. Admin เลือกเพิ่มหรือแก้ไขหมวดหมู่
3. Admin กรอกชื่อหมวดหมู่
4. Admin กดบันทึก
5. ระบบตรวจสอบและบันทึก

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ชื่อหมวดหมู่ซ้ำหรือว่าง: ระบบแจ้งเตือน
- 2a. ลบหมวดหมู่ที่ยังมีสินค้า: ระบบไม่อนุญาต ต้องย้ายสินค้าออกก่อน

#### UC-20 Manage Add-ons

**ผู้กระทำ:** Admin

**คำอธิบาย:** จัดการท็อปปิ้งส่วนกลาง (Add-ons) ได้แก่ สร้าง แก้ไข ลบ และเปิด/ปิดใช้งาน โดยมีชื่อ คำอธิบายย่อ และราคาเพิ่ม รวมถึงค้นหาและกรองตามหมวดหมู่ (ทั้งหมด / กาแฟ / ชา)

**เงื่อนไขก่อน:** Admin เข้าสู่ระบบแล้ว

**เงื่อนไขหลัง:** รายการ Add-on ถูกอัปเดต และการเปลี่ยนแปลงมีผลกับทุกเมนูที่ใช้ Add-on นั้น

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้าจัดการ Add-ons
2. Admin เลือกสร้างใหม่ แก้ไข ลบ หรือสลับสถานะเปิด/ปิด
3. กรณีสร้างหรือแก้ไข Admin กรอกชื่อ คำอธิบายย่อ และราคา แล้วกดบันทึก
4. กรณีลบ ระบบขอให้ยืนยันก่อน
5. ระบบตรวจสอบและอัปเดตรายการ

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ไม่กรอกชื่อ ชื่อซ้ำ หรือราคาติดลบ: ระบบแจ้งเตือนและไม่บันทึก
- 4a. Admin ยกเลิกการลบ: ระบบคงข้อมูลเดิม

#### UC-21 Link Add-ons to Product

**ผู้กระทำ:** Admin

**คำอธิบาย:** เลือกว่า Add-on ส่วนกลางตัวใดจะนำไปใช้กับสินค้าแต่ละรายการ

**เงื่อนไขก่อน:** มี Add-on และสินค้าอยู่ในระบบ

**เงื่อนไขหลัง:** สินค้าถูกผูกกับ Add-on ที่เลือก และ Add-on จะปรากฏในหน้าต่างตัวเลือกเมื่อสั่งสินค้านั้น (UC-08)

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้าแก้ไขสินค้า
2. ระบบแสดงรายการ Add-on ทั้งหมด
3. Admin เลือกหรือยกเลิกการเลือก Add-on ที่ต้องการ
4. Admin กดบันทึก
5. ระบบบันทึกการผูกข้อมูลกับสินค้า

**ลำดับเหตุการณ์ทางเลือก**

- 3a. Admin เลือกสร้าง Add-on ใหม่จากหน้านี้: ระบบเปิดฟอร์มสร้าง Add-on โดยระบุชื่อเมนูที่กำลังแก้ไข
- Add-on ที่ปิดใช้งานจะไม่แสดงในหน้าสั่งซื้อ แม้จะผูกไว้

#### UC-22 Manage Promotions

**ผู้กระทำ:** Admin

**คำอธิบาย:** สร้าง แก้ไข ลบ และเปิด/ปิดโปรโมชัน (ชื่อ ประเภทส่วนลด เงื่อนไข และช่วงเวลา)

**เงื่อนไขก่อน:** Admin เข้าสู่ระบบแล้ว

**เงื่อนไขหลัง:** โปรโมชันถูกอัปเดตและพร้อมให้เลือกใช้ใน UC-09

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้าจัดการโปรโมชัน
2. Admin เลือกสร้างหรือแก้ไขโปรโมชัน
3. Admin กรอกรายละเอียดและกำหนดช่วงเวลา
4. Admin กดบันทึก
5. ระบบตรวจสอบและบันทึก

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ช่วงวันที่ไม่ถูกต้องหรือข้อมูลไม่ครบ: ระบบแจ้งเตือนและไม่บันทึก

#### UC-23 View Sales Reports

**ผู้กระทำ:** Admin

**คำอธิบาย:** ดูรายงานยอดขายตามช่วงเวลา เช่น ยอดขายรวม จำนวนออเดอร์ สินค้าขายดี และยอดแยกตามวิธีชำระเงิน

**เงื่อนไขก่อน:** Admin เข้าสู่ระบบแล้ว

**เงื่อนไขหลัง:** Admin เห็นข้อมูลสรุปยอดขายตามที่เลือก

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้ารายงานยอดขาย
2. Admin เลือกช่วงเวลา (รายวัน / รายเดือน / กำหนดเอง)
3. ระบบรวบรวมข้อมูลออเดอร์ที่ชำระแล้วในช่วงนั้น
4. ระบบแสดงสรุปและรายละเอียดของรายงาน

**ลำดับเหตุการณ์ทางเลือก**

- 4a. ไม่มีข้อมูลในช่วงเวลาที่เลือก: ระบบแจ้งว่าไม่มีข้อมูล

#### UC-24 Manage Users & Passwords

**ผู้กระทำ:** Admin

**คำอธิบาย:** เพิ่ม แก้ไข ปิดใช้งานบัญชีผู้ใช้ กำหนดบทบาท (Cashier / Admin) และรีเซ็ตรหัสผ่านให้ผู้ใช้

**เงื่อนไขก่อน:** Admin เข้าสู่ระบบแล้ว

**เงื่อนไขหลัง:** ข้อมูลบัญชีผู้ใช้หรือรหัสผ่านถูกอัปเดต

**ลำดับเหตุการณ์หลัก**

1. Admin เปิดหน้าจัดการผู้ใช้
2. Admin เลือกเพิ่มผู้ใช้ แก้ไขผู้ใช้ หรือรีเซ็ตรหัสผ่าน
3. Admin กรอกข้อมูลที่จำเป็น เช่น ชื่อผู้ใช้ ชื่อ-นามสกุล บทบาท และรหัสผ่านชั่วคราว
4. Admin กดบันทึก
5. ระบบตรวจสอบ เข้ารหัสรหัสผ่าน และบันทึกข้อมูล

**ลำดับเหตุการณ์ทางเลือก**

- 5a. ชื่อผู้ใช้ซ้ำหรือข้อมูลไม่ครบ: ระบบแจ้งเตือนและไม่บันทึก
- 2a. Admin พยายามปิดใช้งานบัญชีของตนเอง: ระบบไม่อนุญาต
